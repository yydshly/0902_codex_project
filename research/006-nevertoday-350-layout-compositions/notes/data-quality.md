# v2 数据质量边界

## 已验证事实

- 固定版本 catalog 有 350 项连续 ID、350 个唯一名称和 350 个唯一图片路径；
- JSON/CSV、文件名和图片哈希可以保持内部一致；
- 图片海报本身带有醒目的中英文大标题，可用于语义核验；
- 上游验证脚本没有读取图内标题。

## 社区报告

[Issue #1](https://github.com/nevertoday/350-layout-compositions/issues/1) 在 2026-09-03 仍为 open。报告者称抽查 11 张约 10 张错位，并通过 OCR 与人工复核得到：

- 350 张海报实际对应 339 个不同概念；
- 11 个概念有两个视觉变体；
- 11 个 catalog 概念没有对应海报。

这些全量数字来自 issue 报告，本研究没有重新对 350 张高清图执行完整 OCR，因此不把它们标为独立复现结果。

这组目的性抽样覆盖 8 个一级分类的起始项及一个网页 UI 项，不能作为随机抽样错位率；它足以证明问题并非单个损坏文件。

## 对机器使用的影响

| 使用方式 | 风险 |
| --- | --- |
| 人工随意浏览 | 中；仍能获得视觉启发，但名称可能误导 |
| 按名称检索 | 高；召回图片可能讲的是另一个概念 |
| 多模态 RAG | 很高；错误标签会进入向量和回答上下文 |
| 监督训练或分类评测 | 很高；产生系统性标签污染和虚假指标 |
| 自动版式推荐 | 很高；推荐理由与视觉结果可能矛盾 |

## 建议修复顺序

1. 对 350 张高清图提取顶部中英文大标题；
2. 规范化“原则、构图、布局、版式”等后缀，和 350 个概念名称做模糊匹配；
3. 用一对多和零匹配发现重复与缺失；
4. 人工复核低置信度、跨分类和一对多结果；
5. 生成独立的 `semantic_manifest.json`，保留原文件 ID 与修复后概念 ID；
6. 在 CI 中增加“图内标题 ↔ manifest”检查，不只验证哈希；
7. 固定数据版本，避免直接依赖会漂移的 `main` CDN。

不要通过直接重命名并覆盖历史来隐藏问题。保留 `source_asset_id`、`concept_id`、`variant`、`match_method`、`confidence` 和 `reviewed_by`，才能让修复可审计。
