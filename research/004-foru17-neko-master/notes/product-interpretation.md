# Neko Master：我们的理解与后续恢复点

## 一句话判断

Neko Master 是运行在 Clash/Mihomo、Surge 等代理网关控制接口之上的**流量遥测采集与分析层**。它不是代理内核，不负责转发流量，也不是抓包、DPI 或完整的 AI API 可观测平台。

## 能力分层

| 层次 | 当前判断 | 归属 |
| --- | --- | --- |
| 数据源 | 通过 Clash/Mihomo WebSocket、Surge HTTP 或远程 Agent 获取网关连接元数据 | 上游已有 |
| 实时语义 | 把连接累计值转换成增量，处理去重、计数器回退、网关重启和批量上报 | 上游核心价值 |
| 存储查询 | SQLite 默认存储；可选 ClickHouse 双写、读路由与失败回退 | 上游已有 |
| 分析展示 | 按域名、IP、国家、代理链、设备、规则和后端健康动态聚合与下钻 | 上游已有 |
| 本仓库 Demo | 用确定性合成数据完整演示能力面与关键算法语义 | 已完成，不代表真实接入 |
| 真实数据接入 | 启用并保护网关控制接口，运行 collector，再用真实 API/WebSocket 替换 Mock 数据源 | 需要环境适配 |
| AI 产品层 | AI 工具识别、进程归因、Token/成本、异常告警、审计和团队治理 | 需要二次建设及补充数据源 |

## 对关键问题的统一回答

### 它是不是网关流量分析工具？

是，但更准确的说法是“**基于代理网关控制面的流量分析工具**”。它消费网关已经产生的连接状态，而不是自己成为网关或直接捕获网络数据包。

### 它能否接入真实数据并动态分析？

可以。上游会持续读取受支持网关的连接快照，将累计上传/下载值换算为增量，再写入实时层和持久化层；界面查询的是“数据库基线 + 尚未落库的实时增量”。因此它具备实时更新和历史多维分析能力，而不是静态报表生成器。

### 当前网页读取的是不是本机数据？

不是。当前网页是离线、确定性的合成数据实验，用于验证信息架构、交互和差分语义。它不会读取本机代理配置、连接、密钥或数据包。

### 当前电脑上的代理是否具备接入条件？

部分具备。只读检查确认 Mihomo 正在运行、TUN 已启用且存在活跃连接；但 external controller 当前关闭，因此 Neko Master 还无法读取连接数据。真实接入需要显式开启控制接口、限制监听地址并配置强密钥。

### 真实接入之后能看到什么？

能够观察经过受支持网关且由控制 API 暴露的域名、目标 IP、源 IP、上下行字节、规则和代理链等元数据。它默认看不到 HTTPS 明文、提示词、响应正文、可靠的进程身份、绕过网关的流量、Token 数量或真实 API 费用。

## 对我们的意义

值得复用的是底层遥测管线，而不是复制页面：

1. 累计计数器到增量事件的转换与回退语义；
2. 持久化基线加内存热增量的低延迟查询模型；
3. Direct 与 Agent 共享同一领域事件的部署方式；
4. SQLite 到 ClickHouse 的渐进、可回退迁移路径；
5. 域名、IP、代理、规则、设备等多维写时物化模型。

如果建设 AI 流量治理产品，还需要另外补充终端进程事件、应用或 API 网关日志、模型价格与身份权限数据。仅靠代理连接元数据不能可靠推导提示词、Token 和费用。

## 后续恢复点

后续继续时，从“真实 Mihomo 只读接入 PoC”开始，无需重新研究架构：

1. 备份 Clash Verge/Mihomo 当前配置；
2. 将 external controller 仅绑定到可信地址，生成并保存强密钥；
3. 启动上游 collector，验证版本、认证和 `/connections` 数据；
4. 对比网关累计计数、collector 增量和查询聚合，验证重启与断线语义；
5. 将 Demo 的数据适配层切换为真实 API/WebSocket，同时保留 Mock 模式；
6. 完成真实数据基线后，再决定是否建设进程归因、成本、告警和团队治理。

## PoC 完成条件

- 控制接口不暴露到非预期网络，密钥不进入仓库或浏览器日志；
- 能稳定展示本机真实域名/IP、上下行流量、规则和代理链；
- 暂停、恢复、网关重启和计数器回退不会造成明显重复或丢失；
- 真实模式与 Mock 模式可以明确区分和独立切换；
- 提供关闭控制接口、停止 collector 和恢复原配置的回滚步骤。
