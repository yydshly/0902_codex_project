# Aurelia 项目总览：案例、能力与研究结论

> 快照日期：2026-09-04
>
> 范围：`apps/001-holtsetio-aurelia/` 与 `research/001-holtsetio-aurelia/`
>
> 用途：作为项目的统一入口，区分上游事实、已验证能力、体验原型、业务探索和后续研究。

可运行网页：[`summary.html`](../../../apps/001-holtsetio-aurelia/summary.html)

## 一句话结论

这个项目已经不是“水母效果复刻”，而是一项围绕 **程序化形态、GPU 软体物理、连续状态、交互反馈与业务表达** 的研究。它已经证明 Aurelia 的方法可以迁移，但也证明了：**技术链可以复用，作品品质不会自动复用；只有选题、结构、运动、材质、环境和交互形成同一条因果链时，才可能接近原水母的完成度。**

## 1. 项目现在拥有什么

项目目前包含五类资产：

1. **一个正式质量基准**：原 Aurelia 程序化水母。
2. **两类研究工具**：参数实验室、方向图谱与旗舰对照场。
3. **七组机制与表现样例**：声音形态、声场雕塑、活体品牌、雨伞、晾衣绳、地铁、书法、窗帘。
4. **一个业务纵向切片**：Weatherproof 产品官网原型。
5. **一个暂时冻结的旗舰探索**：墨光乌贼群。

这些交付物不能被理解为十五个成熟产品。更准确的结构是：

```text
原水母：质量基准与源代码证据
    ↓
实验室 / 图谱：理解、测量和组织方法
    ↓
机制样例：验证方法能否迁移
    ↓
业务样例：验证视觉状态能否进入真实用户路径
    ↓
旗舰探索：验证能否形成新的完整作品
```

## 3. 已经验证的能力地图

### 3.1 渲染与 GPU 计算

| 能力 | 当前证据 | 复用价值 |
| --- | --- | --- |
| Three.js WebGPU 渲染 | 所有核心 3D 页面使用 `WebGPURenderer` | 统一场景、相机、材质与计算管线 |

## 4. 原水母为什么仍然是最佳案例

原水母的优势不是节点数量更大或 Bloom 更亮，而是所有层共享一个生物学上合理的原因：

```text
钟体收缩相位
  → 解析钟体变形
  → 钟缘肌肉与弹簧受力
  → 口腕和触手出现延迟拖尾
  → 身体获得向上位移和方向变化
  → 皮肤脉冲、charge 与辉光同步
  → 环境雾、浮游物和群体相位强化深海空间
```

这条链同时覆盖：

- **轮廓**：径向钟体一眼可辨；
- **结构**：主运动和次级运动有明确连接；
- **材质**：半透明身体天然允许内部结构与发光；
- **环境**：深海为漂浮、慢动作和体积感提供合理介质；
- **群体**：多个独立相位带来长期非重复节奏；
- **交互**：指针靠近可以被解释为外部刺激，而不是任意控制器。

后续选题必须先拥有类似的完整因果闭环，再讨论建模和特效。

## 5. 已沉淀的核心研究结论

### 5.1 可迁移的是方法，不是水母外观

最有价值的模式是：**解析或受控的主形态 + GPU 物理次级运动 + 同一状态驱动材质、声音和反馈**。声场雕塑、活体品牌、雨伞和城市网络已经证明这套方法可以离开水母。

### 5.2 “有物理”不等于“看得见物理”

晾衣绳、窗帘和乌贼的多轮返工都暴露了同一问题：GPU 数值发生变化，不代表用户能从轮廓、遮挡、传播时间和镜头中读出变化。可见运动必须成为验收项，而不是由节点位移间接推断。

### 5.3 “是真 3D”不等于“具有空间体验”

PerspectiveCamera、三维 Mesh 和 WebGPU 只能证明技术上是 3D。没有可读厚度、前后遮挡、视角变化、尺度参照和正确拖动语义时，体验仍会像二维插画。

### 5.4 程序化建模有适用边界

水母、膜、场线、晶体、网络等结构与数学形式高度一致，程序化生成可以成为最终美术。乌贼、服装、人物和真实商品拥有严格的解剖或工业细节，程序化 primitive 通常只能达到 L1–L3 原型质量，需要高质量模型、材质扫描和绑定管线。

### 5.5 输入、状态和表现应解耦

`音频 / 指针 / 数据 / 业务事件 → 标准化状态 → 物理与表现映射` 已在多个页面验证。它使同一作品可以替换音乐、实时数据或业务输入，而不重写整个场景。

### 5.6 单一因果链优于效果叠加

粒子、辉光、音效和相机如果不能解释同一事件，只会增加噪声。原水母最值得学习的是“一因多果”的一致性，而不是特效数量。

### 5.7 业务价值来自解释与决策，不来自背景装饰

Weatherproof 证明，3D 场景只有进入“用户选择 → 状态变化 → 推荐理由 → 商品比较 → 行动转化”路径时，才从主视觉变成产品能力。WebGPU 应提供证据和记忆点，DOM 继续承担可读内容与任务。

### 5.8 失败样例也是项目资产

竞技场和乌贼探索明确暴露了选题、资产、运动模型与因果耦合的门槛。这些结果应保留为选择规则，而不是通过持续加效果掩盖。

## 6. 已形成的研究体系

### 6.1 十个创意方向

1. Resonant Matter / 声场雕塑
2. Living Identity / 活体品牌
3. Playable Space / 可演奏空间
4. Gravity Loom / 引力织体
5. Signal Ecology / 数据生命网络
6. Memory Alloy / 记忆合金
7. Acoustic Black Hole / 声学黑洞
8. Topological Climate / 拓扑气候
9. Crystal Syntax / 晶体语法
10. Collective Glyph / 群体字形

前两个方向已有正式独立页面；其余是研究候选，不应被描述为已交付作品。

### 6.2 十二个现实观察

雨落伞面、风中晾衣绳、地铁拥堵、毛笔墨水、树影窗帘、磁铁铁屑、群体同步、蛛网露珠、潮汐沙面、玻璃凝露、鸟群鱼群、根系菌丝。

它们不是造型清单，而是用于提取以下共同语法：

```text
固定点 / 自由度 / 约束 / 场 / 冲击 / 历史 / 恢复
```

### 6.3 十三层技术研究

程序化拓扑、GPU 状态存储、约束求解、解析锚点桥、外力与场、接触与碰撞、缓冲驱动表面、输入标准化、历史与重放、空间声音与声化、反馈与叙事、可观测性与验证、产品化边界。

### 6.4 十种交互模块

局部排斥、拖拽拨弦、速度尾流、长按蓄能、吸引 / 排斥反转、撕裂与自愈、区域传导、轨迹记忆、深度涡旋、结构变异。

### 6.5 五项作品质量门

1. **因果可读**：输入、传播、结果和消退能被用户理解。
2. **数值稳定**：极端输入和长时间运行保持有限、可恢复。
3. **预算明确**：节点、约束、资产、后处理和设备档位有真实预算。
4. **数据诚实**：演示、合成、推断和真实数据边界明确。
5. **降级保义**：无 WebGPU、静音、低动态和键盘路径仍表达核心意义。

项目实践还补充了第六项：

6. **审美与资产门**：机制通过不能代替主体轮廓、资产质量、构图、材质和环境达到作品标准。

## 7. 可以抽取成项目内核的模块

当前代码已经提供原型证据，但尚未被正式抽成稳定公共 API。建议未来按下面的边界整理：

| 候选内核 | 职责 | 已有来源 |
| --- | --- | --- |
| `PhysicsRuntime` | 物理缓冲、固定子步、计算调度、reset 与诊断 | 上游 `VerletPhysics` 及各页面 bridge |
| `TopologyBuilder` | 链、网格、膜、字形、图与邻接关系生成 | 水母、Resonance、Identity、Rain、Curtain |
| `AnchorBridge` | 把解析形态、字形、骨架、数据目标写入固定锚 | 水母、Identity、Metro、Rain |
| `FieldInput` | 指针、风、雨、音频、拥堵等外力的统一接口 | Morph、Rain、Windline、Metro |
| `SurfaceBinding` | 物理点到管、带、膜或外部 GLB 顶点的绑定 | 水母触手 / 口腕、Rain、Windline |
| `InteractionController` | hover / press / drag / release、点击与 orbit 意图分流 | Rain、Windline、Cuttlefish |
| `AudioMapper` | 连续状态声化、频谱输入和事件音效 | Morph、Resonance、Rain、Curtain |
| `Diagnostics` | finite readback、帧时、节点 / 约束计数与状态暴露 | 多个 LIVE 样例 |
| `ExperienceFallback` | WebGPU fallback、reduced-motion、键盘与 DOM 保义 | Atlas、Weatherproof 及各 Field Prototype |

### 工程层

- 上游没有公共 API、类型、测试和语义化版本；当前通过固定 commit 和构建适配使用。
- 各页面存在重复的 renderer、输入、诊断、fallback 和生命周期逻辑，尚未形成统一运行时。
- 缺少跨 GPU / 浏览器 / 移动设备的正式性能矩阵和显存预算。
- 缺少确定性 fixture、历史快照、自动视觉差异和长时间压力测试。

### 物理层

- 通用质量、XPBD 柔度、塑性、断裂 / 重连和迟滞没有完成。
- 碰撞、自碰撞、摩擦和高速接触没有形成可复用实现。
- 多场耦合、空间分区、邻域搜索与动态拓扑仍处于研究阶段。

### 视觉与资产层

- 缺少从概念图 / 网络资产到经过许可、清理、UV / PBR、绑定、压缩和浏览器预算的正式资产管线。
- 多个样例的主体、环境和镜头仍只达到研究原型质量。
- 尚未形成跨页面统一但不过度同质化的艺术指导系统。

### 产品层

- 只有 Weatherproof 完成了业务纵向切片；没有真实 PIM、库存、检测、CRM、支付或数据治理。
- 还没有可复用的“业务状态 → 物理状态 → 可解释结果”配置层。
- 发布、观测、事件分析、多语言与内容管理尚未系统化。

## 9. 当前项目价值

### 对创意研发

建立了一套从现实观察抽取物理语法的方法，而不是只积累视觉风格参考。

### 对前端与图形技术

获得了 WebGPU Compute、Storage Buffer、TSL 表面和物理—渲染同缓冲的真实工程证据。

### 对设计与品牌

证明品牌字形、声音、天气、城市数据和空间材料可以拥有持续状态、记忆和触感，而不是一次性动画。

### 对产品业务

证明实时视觉可以进入诊断、推荐、比较、解释和转化链路；同时明确了真实数据与资产接入的边界。

### 对决策

最重要的收益不是已经找到“第二只水母”，而是已经得到一套排除低潜力选题、识别资产瓶颈和判断作品是否值得深挖的标准。

## 10. 当前阶段决策

1. 保留全部已有案例，不删除、不覆盖原水母基准。
2. 乌贼作为探索性样例冻结，暂不继续局部优化。
3. 暂停按顺序新增现实案例，避免案例数量继续快于质量沉淀。
4. 将后续工作重心转向：公共能力抽取、质量基准、选题机制和旗舰作品前置研究。
5. 新作品立项前必须同时通过：选题因果闭环、程序化 / 资产路线、运动模型、材质角色、环境介质、交互语义和设备预算评审。
