# 研究区

`research/` 保存每个优秀 GitHub 项目或主题的结构化研究。每个一级目录是一项独立研究，目录名以稳定三位编号开头：

```text
research/001-owner-repository/
```

编号只表示登记顺序。已发布编号不修改、不复用；新条目永远从当前最大编号继续递增。

## 推荐结构

```text
research/001-owner-repository/
├─ README.md                 # 事实入口与研究摘要
├─ notes/                    # 可选：专题笔记
├─ experiments/              # 可选：最小复现实验
├─ patches/                  # 可选：补丁或差异文件
└─ assets/
   ├─ README.md              # 图片清单、说明、来源与权利边界
   ├─ cover.webp             # 必需：核心演示图或架构/能力总图
   └─ screenshots/           # 可选：关键截图
```

从 [`_template/README.md`](_template/README.md) 开始创建条目。较长主题拆入 `notes/`，但条目 README 必须能独立说明研究对象、基线、结论、证据入口和限制。

## 内容边界

- 记录“为什么值得研究”和“哪些结论已经验证”，不只做功能摘录。
- 对事实、推断和个人评价作清晰区分。
- 记录研究所依据的 commit、tag 或 release。
- 记录上游许可证；引用代码或素材时保留必要权利声明。
- 完整上游源码默认不提交，只保留最小复现所需内容。
- 外部截图必须写明截取日期；所有图片必须有替代文本与研究意义说明。
- 每项研究必须提供一张对外核心图：优先使用真实 Demo，缺少代表性界面时制作可追溯的架构、能力或流程总图。
