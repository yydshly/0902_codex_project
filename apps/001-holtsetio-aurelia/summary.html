05 TECHNICAL DEEP DIVE / 技术运行链

每一帧，
到底发生了什么。

核心不是“Three.js 做了一个动画”，而是 CPU 先定义可计算结构，GPU 持续推进状态，同一批状态再驱动几何、材质、声音与产品界面。

  1. 00 / OBSERVE

    现实或业务输入

    声音、天气、指针、雨滴、风、压力、流量，先被压缩成稳定、可解释的控制量。

    raw input → normalized state
  2. 01 / BUILD

    CPU 构造拓扑

    生成节点、锚点、边、约束、表面索引和绑定权重；这一阶段决定对象能怎样运动。

    points · springs · indices · weights
  3. 02 / STORE

    GPU 保存状态

    位置、上一帧位置、速度、约束和事件历史进入 Storage Buffer，避免逐帧 CPU 回读。

    position · velocity · constraint · history
  4. 03 / SOLVE

    固定步长求解

    外力、锚点、弹簧、阻尼、恢复和预算钳制按子步执行；不同案例使用不同 steps/s。

    force → integrate → constrain → guard
  5. 04 / BIND

    同缓冲驱动表面

    渲染顶点直接读取物理状态或代理权重，因此布、膜、字形和附肢不会与物理脱节。

    storage state → vertex surface
  6. 05 / EXPRESS

    多通道反馈

    位移、应力、湿度和相位继续映射到材质、Bloom、声音、DOM 解释和业务 CTA。

    one cause → many readable effects

01 八条最重要的研究结论
  1. 可迁移的是方法，不是水母外观。
  2. “有物理”不等于“看得见物理”。
  3. “是真 3D”不等于具有空间体验。
  4. 程序化建模有明确适用边界。
  5. 输入、状态与表现应当解耦。
  6. 单一因果链优于效果叠加。
  7. 业务价值来自解释与决策，不来自背景装饰。
  8. 失败样例同样是选择和质量研究的资产。
